# Core 产品边界

InkLayer Core 负责 React、Vue、Vanilla 及未来使用方之间必须保持一致的行为；框架适配器负责产品组合与表现。划分依据是行为一致性，而不是一个功能是否带有可见 UI。

## 职责判断

如果某项能力在两个框架适配器中分别修改，会改变 PDF 解释、页面坐标、批注数据、文档内直接操作、资源所有权或持久化/导出结果，它就属于 Core。

如果它控制产品布局、品牌、工作流组合、路由、文案或业务策略，则属于框架适配器。很多可见功能横跨两层：Core 提供无头模型和浏览器引擎行为，框架负责外围控件。

## 必须遵守的拆分

| 能力 | Core | 框架适配器 |
|---|---|---|
| Viewer | 加载、页面、统一数值/自适应缩放、捏合锚点、渲染生命周期、导航 | 应用布局和路由状态 |
| 缩略图 | 渲染队列、缓存、取消、页面身份 | 侧边栏/网格表现 |
| 目录 | 提取、目标解析、导航目标 | 树形表现和展开状态 |
| 搜索 | 提取、匹配、结果顺序、当前结果导航 | 搜索框和结果列表 |
| 文字选择 | PDF.js TextLayer、DOM Range 归一化、选择状态与页面空间矩形 | 上下文操作菜单 |
| 密码/安全 | 密码请求生命周期、重试/取消、权限归一化 | 密码对话框和策略文案 |
| 页面布局 | 单页/连续/对页；虚拟页面壳、预渲染、缩放、导航、可见页生命周期 | 模式控件、滚动条样式和外围布局 |
| 水印 | 已验证策略、Canvas/PDF 渲染 | 身份数据和策略控件 |
| 打印 | 权限执行、矢量/栅格合成、水印/批注合并、浏览器资源生命周期 | 打印选项和命令 UI |
| 批注交互 | 命中测试、选择、拖动、缩放、旋转、端点/顶点编辑 | 工具栏和外观控件 |
| 键盘/无障碍 | 文档内焦点、Canvas 语义镜像、移动/删除、FreeText 焦点、减弱动态效果执行 | 有标签的产品控件、菜单/对话框焦点顺序、本地化流程文案 |
| 协作 | 规范评论、权限、引用和编号 | 面板、对话框和用户文案 |
| 导出 | 确定性的 PDF/XLSX 字节 | 命名、下载、上传和持久化策略 |

## 交互不变量

- 直接操作必须连续响应并一对一跟随指针。
- 双指捏合与 Ctrl/Meta + 滚轮缩放保持手势中点，连续更新 PDF viewport scale，并受 Core 策略限制。
- 已有批注只能在选择模式下拖动。
- 变换控件取决于批注几何；通用矩形 Transformer 不能覆盖所有类型。
- 多笔 Freehand 合并、Free-highlight 轴向修正，以及 Polygon/Cloud 的开放预览与双击结束语义属于 Core。
- 文字批注必须源于真实页面 TextLayer 选择，并由 Core 归一化后创建。
- `text-select` 把输入交给 TextLayer；`select` 保留批注命中与直接操作，不让框架适配器仲裁 DOM/Canvas 事件。
- 跨页 DOM 选择按顺序输出为页内片段，规范批注仍保持页面级归属。
- 密码绝不进入快照、错误、日志、存储或普通事件。
- 框架适配器不接收 Konva 节点，也不持久化框架专属批注模型。
- Core 不设置 `role="application"`；Canvas 批注具有稳定原生按钮替代与可见焦点，适配器负责外围控件语义，并利用文字选择来源交接菜单焦点。
- Viewer 子功能按 generation 管理，替换文档或销毁时释放页面任务、Canvas、TextLayer、搜索任务与缩略图缓存。
- 虚拟多页流只挂载预渲染窗口内的页面，以结构化 Core 错误报告异步失败，并在释放离屏资源时保持页面身份稳定。
- 栅格打印输出是临时、未加密、仅图片的产物；适配器不能把它作为受保护源文档的替代品暴露。

## 已验证的修正结果

Core 已提供经过测试的缩略图、目录、搜索、目标解析、跨页 TextLayer 选择、虚拟连续页面生命周期、安全栅格打印、密码、权限和水印操作。批注拖动/变换按工具类型实现，Vanilla 应用在 Chromium 中覆盖这些路径。本文继续作为未来 React/Vue 工作的职责判断依据。
